Comprehensive Technical Architecture & Project Development Report

1. Executive Summary & Project Abstract

HazeEngine is a zero-install, cloud-integrated web platform combining an Interactive Visual Novel Studio with a full-fledged Digital Audio Workstation (DAW). Historically, digital narrative creators were forced to juggle disjointed desktop software—using narrative tools (Ren'Py, Twine) alongside complex commercial audio workstations (FL Studio, Ableton Live). This created severe friction, licensing costs, platform dependency, and distribution bottlenecks.

HazeEngine eliminates this divide by embedding both a node-based visual novel studio and a 4-channel synthesizer/step sequencer directly into modern web browsers. Creators write branching storylines, position character sprites, compose original multi-channel soundtracks, bind music directly to scenes, and instantly distribute their work via permanent public URLs (/play/:id and /music/:id) with zero compilation steps.

2. High-Level Architecture & Design Philosophy

2.1 Dual-Tier Topology (Cloud Primary + Local Resilient Fallback)

The system is built on an adaptive multi-tier architecture that operates transparently across both cloud and local environments:

  • Cloud Mode (Primary - Supabase): Leverages Supabase PostgreSQL, GoTrue Auth (JWT session management), Row Level Security (RLS), and S3-compatible cloud storage buckets (images and audio).
  • Local Mode (Offline Fallback - Express Server): If internet connectivity drops or Supabase credentials are absent, the application gracefully degrades to an Express.js server on port 3001 with local JSON persistence (data/projects.json) and disk storage (uploads/).

3. Detailed Subsystem Architecture

3.1 Digital Audio Workstation (DAW)

Built upon Tone.js and the Web Audio API, decoupled from React's render thread to prevent audio jitter. Synthesizers include subtractive oscillators, a 2-operator FM synth for bass, a 6-voice polyphonic synth for chords, and synthesized drum instruments (Membrane kick, Noise snare/hat, Metal rimshot). Offline audio rendering computes PCM audio at 44.1 kHz, converted to 16-bit WAV and encoded to MP3 via lamejs.

3.2 Visual Novel Game Engine

Visual novel storylines are stored as a directed scene graph. Features real-time character-by-character typewriter streaming (30ms rate), normalized percentage coordinate positioning for sprite scaling across screen sizes, and dynamic target scene linking for interactive choices.

3.3 Security & Hardening

Row Level Security restricts database writes to authenticated resource owners while permitting anonymous public reads for published games and music. Express upload endpoints enforce an allowed category whitelist and path.basename() regex sanitization to eliminate path traversal vulnerabilities.

4. Complete Development Lifecycle in Phases

  • Phase 1: Environment, Tooling & Design System: Vite 8, React 19, Tailwind v4, design tokens, responsive layout, animated landing page, and Express backend.
  • Phase 2: Visual Novel Core Engine: SceneEditor.jsx three-pane layout, DialogueEditor.jsx, ChoiceEditor.jsx, and typewriter preview player.
  • Phase 3: Web-Based Digital Audio Workstation: StepSequencer.jsx, AudioEngine.js multi-synth engine, TransportBar.jsx, scale transpositions, and MP3 exporter.
  • Phase 4: User Authentication & Project Dashboard: Supabase Auth integration, profile sync triggers, project dashboard grid, and project management workflows.
  • Phase 5: Audio-Visual Integration: AudioTrackPicker.jsx, scene audio loop bindings, and backward compatibility.
  • Phase 6: MVP Publishing System: publishStore.js data layer, PublishModal.jsx, public player pages (/play/:id and /music/:id), Explore catalog, and My Publications dashboard.
  • Phase 7: Optimization, Security & Brand Polish: Rolldown vendor chunk-splitting (<500ms build), path traversal mitigation, vector SVG LogoMark, and data store sanitation.
